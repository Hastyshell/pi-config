# Project Workflow

Use this workflow for code reading, editing, refactoring, debugging, or configuration tasks:

1. Quickly inspect the project structure and identify relevant files.
2. Read the necessary context before making changes; do not infer behavior from filenames alone.
3. Make small, focused changes. Avoid unrelated refactors or opportunistic cleanup.
4. If tests or checks exist, run the smallest relevant set for the change.
5. Summarize the result: files changed, why they changed, validation performed, and any remaining follow-up items.

Respond in Chinese by default, unless the user explicitly requests another language.
